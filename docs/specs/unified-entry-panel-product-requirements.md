# 統一入口浮動面板：產品需求與互動規格

狀態：產品決策已收斂，待進入架構規劃

本文件定義 ClipAI 統一入口浮動面板的使用者需求、資訊架構與可驗收互動。它刻意不定義程式模組、資料結構、事件流、儲存方式或技術選型；那些屬於下一階段的架構規劃。

本文件是此需求的驗收依據。原型 [mock_unified_entry_panel.html](/C:/Users/88698/ClipAI_v2.worktrees/next_gen/scripts/mock_unified_entry_panel.html) 與截圖 [mock_unified_entry_panel_snapshot.png](/C:/Users/88698/ClipAI_v2.worktrees/next_gen/scripts/mock_unified_entry_panel_snapshot.png) 用來傳達視覺語言與密度感；若原型和本文的功能排序或行為不同，以本文為準。

## 1. 產品意圖

ClipAI 是使用者思考與寫作時的輕量副駕。它要降低「看見一段內容」到「採取合適下一步」之間的操作摩擦，但不替使用者做立場、價值、關係、因果或最終選擇。

統一入口不是新的聊天視窗、工作區或功能總表，而是一個在游標附近短暫出現的輕量啟動器。它同時服務兩種人：

- 初次或不熟悉的使用者，透過三個旗艦情境理解 ClipAI 能幫什麼。
- 已養成習慣的使用者，透過最近成功使用的 action 立即重複操作。

產品必須保留以下原則：

- 減少不必要的操作與閱讀摩擦，但在英文學習、領域學習等需要理解的情境，不把學習本身偷換成完全代勞。
- AI 優先承接操作與脈絡轉換；判斷方向、立場、品味、價值取捨與最後選擇仍在使用者手上。
- 一個畫面可同時要求使用者理解的關鍵選項控制在 5±2 個內。根目錄的七個直接入口正好是可接受上限，不能再堆入搜尋、設定、說明或其他裝飾性選項。
- 每次明確操作都必須有立即可見的回應；不得在 action 尚未真正完成前宣告成功。

## 2. 範圍與非目標

本需求包含：

- 以 `Ctrl + Alt` 長按開啟的游標附近浮動面板。
- 三個旗艦情境、工具類 action、最近使用 action、鍵盤數字選取、滑鼠點選、Esc 漸進返回，以及資訊密度切換。
- 現有 action 的產品分類、首頁優先級與進階入口。

本需求不包含：

- 新增、刪除或重寫任何 AI action 的任務語意、提示詞或輸出格式。
- 改變既有短按直接快捷鍵的功能。
- 在根目錄加入聊天、搜尋框、設定、快捷鍵教學、歷史全文、推薦內容或大型 side panel。
- 決定 action 資料如何儲存、最近使用如何記錄、面板由何種 UI 技術製作，或任何架構責任分配。

`快捷鍵測試` 已經由 window tray 提供，**不得**再出現在統一入口的「工具」中。

## 3. 觸發與生命週期

### 3.1 開啟

- 使用者必須連續按住 `Ctrl + Alt` **500ms** 才開啟面板；500ms 是全產品統一的長按判斷準則。
- 500ms 前放開任一按鍵，面板不得開啟，也不得殘留半開、閃爍或延遲彈出的狀態。
- 已存在的短按 `Ctrl + Alt + 數字` 直接快捷鍵維持原有意義。使用者在 500ms 前輸入數字時，應走既有直接快捷鍵，不得同時開啟面板或重複觸發 action。
- 面板出現在游標附近，而非固定佔據螢幕邊緣。它要像 tray 選單一樣輕，不得變成常駐側欄。

### 3.2 關閉與返回

- 根目錄右上角固定提示 `Esc 關閉`；按一次 Esc 立即關閉面板。
- 非根目錄右上角固定提示 `Esc 返回`；按一次 Esc 回到上一層，而非直接關閉。
- 在「更多功能」頁面按 Esc 必須回到原本的情境頁；在情境頁按 Esc 才回到根目錄。
- Esc 是可預期的漸進式煞車，不能要求使用者記憶其他返回鍵，也不能把 Esc 做成醒目的行銷或主題色按鈕。

### 3.3 選取 action 後的回應

- 滑鼠點選與數字鍵選取必須等價，且都要立即顯示被接受的回應，例如選取中的視覺狀態，或後續 action 的真實 pending／active 狀態。
- Action 的完成、失敗或取消必須反映真實生命週期。沒有執行成功時，不得顯示成功。
- 無法使用的入口不得靜默失效；使用者必須看得出它不可用或收到明確失敗回應。

## 4. 根目錄資訊架構

根目錄同時服務「重複上次有效工作」與「探索 ClipAI 能力」。最近使用與旗艦情境具有同等產品重要性，視覺注意力與可點選難度應約各占一半；這不是硬性像素比例，而是不能讓其中一方淪為次要連結。

### 4.1 最近使用：第一層直接入口

最近使用不得是一個需要再次進入的分類頁。把它藏到第二層，會讓不記得位置的使用者失去最常重複使用的能力。

- 根目錄最上方直接呈現最近三個成功完成的 action，以橫向、等權重的三個按鈕顯示。
- 三個按鈕可直接滑鼠點選，不需要先點「最近使用」。
- 根目錄數字 `0`、`1`、`2` 分別直接執行第一、第二、第三個最近使用的 action。
- 最近使用依最後一次**成功完成**排序；同一 action 只保留最新一筆，避免三格都是同一個功能。
- 最近使用只呈現 action 名稱與必要的輕量提示，不呈現使用者原文、剪貼簿內容、結果全文或其他私人脈絡。
- 若歷史少於三個 action，只顯示實際存在的按鈕，缺少的數字不對應任何 action；三個旗艦情境和工具仍正常顯示。
- 最近使用是「最近成功的重複入口」，不是使用頻率排行、推薦系統或另一套 action 分類。

### 4.2 三旗艦情境與工具

最近使用區下方以四個簡潔分類入口呈現。根目錄總共七個直接選擇，符合 5±2 的認知負荷上限。

| 數字 | 入口 | 使用者問題 | 進入後的目的 |
| --- | --- | --- | --- |
| `3` | 看得懂 | 「這段內容到底在說什麼？」 | 轉譯、說明、閱讀與英文理解 |
| `4` | 寫得出 | 「我知道意思，但怎麼寫成可用文字？」 | 翻譯、壓縮、改寫與語音成稿 |
| `5` | 想清楚 | 「我還沒準備好下結論，怎麼釐清？」 | 結構、盲點、取捨與下一個問題 |
| `6` | 工具 | 「我需要先把內容或脈絡拿進來。」 | OCR、交接與指令審查等工具性能力 |

根目錄不得加入搜尋欄。搜尋只在「更多功能」內出現，避免讓首次使用者一打開就要先猜關鍵字。

## 5. 情境頁與進階功能

選擇看得懂、寫得出或想清楚後，進入該情境頁。每個情境頁的前四個 action 是旗艦入口，固定以 `1` 至 `4` 對應，可用數字鍵立即選取。

- 情境頁可以在詳細模式顯示一句短說明，說明此情境幫使用者完成什麼；精簡模式隱藏說明。
- 旗艦 action 必須是使用者最常需要、最容易理解且最能代表該情境的四個能力，而不是依設定檔或技術順序排列。
- 情境頁底部提供 `+ 更多［情境］功能`。它是中性、低權重的延伸入口，不得使用醒目主題色。
- 「更多功能」頁才顯示搜尋欄與進階 action。進階功能仍可直接點選，但不能搶走四個旗艦 action 的第一視線。
- 工具頁只呈現真實可呼叫的工具類 action；不放導覽、教學或設定項目。

## 6. Action 分類與優先級

以下表格是所有現有 action 的產品歸屬。括號內為既有 canonical action id；前四項為情境頁第一層，其餘列入「更多功能」。顯示名稱可使用較短的產品文案，但不得改變 action 原本任務語意。

| 類別 | 第一層旗艦 action（`1`–`4`） | 進階功能 |
| --- | --- | --- |
| 看得懂 | 翻譯成繁體中文 (`translate_to_traditional_chinese`)、English Companion (`english_companion`)、朋友方式說明 (`explain_like_friend`)、讀懂這段英文 (`reading_friction`) | 文章架構與重要觀點 (`article_structure`)、抽取核心關鍵字 (`extract_keywords`) |
| 寫得出 | 翻譯成英文 (`translate_to_english`)、縮短內容 (`shorten_content`)、私下口吻改寫 (`personal_style_informal`)、語音成稿編輯 (`intent_preserving_dictation_editor`) | Capture an Expression (`expression_retrieval`)、正式口述講稿 (`personal_style_oral`)、正式重點稿 (`personal_style_presentation`) |
| 想清楚 | 麥肯錫金字塔 (`pyramid_position`)、反向挑戰 (`critical_thinking`)、權衡透視 (`tradeoff_perspective`)、提出一個值得思考的問題 (`reflective_question`) | 為想法命名 (`name_idea`)、概念命名 (`name_concept_carefully`)、照亮不變的本質 (`illuminate_essence`)、保存暫時觀點 (`temporary_viewpoint`)、MECE 拆解 (`mece_decomposition`)、最小行動 (`minimum_action`)、SCORE 需求整理 (`structure_score_prompt`) |
| 工具 | OCR／擷取截圖文字 (`extract_screenshot_text`)、AI 對話交接 (`session_handoff`)、Command Copilot (`command_copilot`) | 目前無；未來只有真正的工具型 action 才能加入 |

分類背後的使用者語言必須保持一致：

- 「看得懂」是降低理解門檻，不只是把字換成另一種字。
- 「寫得出」是把意思轉成可直接使用的表達，不替使用者捏造立場或關係拿捏。
- 「想清楚」是照亮結構、盲點與取捨，不替使用者做最終判斷。
- 「工具」處理輸入、交接或可審查的操作輔助，不與三個心智情境競爭。

## 7. 視覺與互動密度

### 7.1 整體語言

- 面板必須小、輕、靠近游標，視覺感受接近 tray 選單，不佔據使用者正在閱讀或寫作的主畫面。
- 使用者可用滑鼠或鍵盤完成同一件事。數字鍵是加速方式，不是藏起滑鼠功能的替代方案。
- 強調色只用於提示使用者目前的可操作情境或已選取項目；不能只為裝飾而使用。
- `Esc 關閉／返回`、`更多功能` 與資訊密度控制都使用中性低權重樣式，不搶奪主題情境或旗艦 action 的注意力。
- 不在 header 再放一個與返回列重複的情境標題或主題色標籤。使用者已從返回列與內容知道自己在哪一層，重複資訊只增加負擔。

### 7.2 單一資訊密度切換鈕

Header 只保留**一個**資訊密度切換鈕。它不是兩顆一點／三點按鈕，也不應同時塞入說明文字。

- 預設是詳細模式：顯示 action 短說明與情境短說明，幫助新使用者建立心智模型。
- 按下後進入精簡模式：隱藏說明文字，只保留 action 名稱、必要鍵位與結構，降低熟練使用者的閱讀摩擦。
- 再按一次回到詳細模式。它只有「詳細」與「精簡」兩個清楚狀態，不增加第三種模式。
- 按鈕以單一滑軌／圓點的開關狀態表達，不以文字佔用 header。未按與按下的差異必須看得出來，但顏色不能是唯一辨識方式。
- 滑鼠懸停或鍵盤聚焦時，Tooltip 必須說明目前狀態與下一次點擊的結果：詳細模式為「顯示詳細說明，點擊切換精簡模式」；精簡模式為「精簡模式，點擊顯示詳細說明」。
- 切換資訊密度不得改變 action 排序、可用性、最近使用內容、數字對應或目前所在頁面。

### 7.3 Header 排版約束

Header 由左至右是產品識別、單一密度切換鈕、Esc 提示。此區是目前 mock 必須持續遵守的約束：

- 文字、切換鈕與 Esc 提示在任何正常顯示比例、字體縮放與面板狀態下都**不得重疊**。
- 切換鈕須有獨立可點擊範圍，與兩側文字保持明確間距；不能因面板想做得更小而壓到產品名稱或 Esc。
- 面板寬度可以為了三個最近使用按鈕與 header 的可讀性微調，但不得犧牲按鈕可點性、文字辨識或形成大面積 side panel。

## 8. 使用者流程

### 流程 A：熟練使用者重複上一個 action

1. 使用者在目前內容上按住 `Ctrl + Alt` 500ms。
2. 游標附近出現面板，根目錄頂端已直接顯示三個最近成功 action。
3. 使用者按 `0`、`1`、`2`，或直接點其中一個按鈕。
4. 該 action 立即進入可見的執行回應；使用者不需要再進「最近使用」第二層。

### 流程 B：不確定要用哪個功能的使用者

1. 使用者開啟面板後，看見看得懂、寫得出、想清楚三個以人類目的命名的旗艦情境。
2. 使用者選擇一個情境，再從四個核心 action 中以 `1`–`4` 或滑鼠選取。
3. 若四個核心 action 都不適合，才開啟「更多功能」搜尋或挑選進階 action。

### 流程 C：熟悉功能後降低閱讀量

1. 使用者看見 header 中單一密度切換鈕。
2. 點擊後，面板留住名稱、鍵位與導覽結構，但隱藏所有解釋文字。
3. 使用者仍可用同一套數字鍵、滑鼠點選與 Esc 操作，不需重新學習。

## 9. 發版品質底線

這裡不是測試架構設計，而是使用者可感知的交付底線。實作階段必須以 Unit Test 與 Integration Test 驗證它們。

- 500ms 長按、提前放開、短按既有快捷鍵、數字鍵與滑鼠選取不會互相重複觸發。
- 最近使用只列成功完成的唯一 action，排序、空狀態與 `0`–`2` 對應正確。
- 根目錄、情境頁與更多頁的 Esc 返回路徑正確，且 header 文案同步反映目前行為。
- 詳細／精簡切換只改變資訊密度，不改變 action 行為或導覽位置；Tooltip 可被滑鼠與鍵盤使用者理解。
- 在真實 Windows 桌面環境中，面板能在游標附近開啟、可用滑鼠點選、鍵盤焦點穩定，且 header 文字與 toggle 不重疊。
- action 的 pending、成功、失敗與取消狀態符合真實結果，不以畫面更新假裝成功。

## 10. 已排除的設計

- 把「最近使用」做成根目錄的一個分類，再要求使用者進第二層挑 action。
- 只用 `0` 對應一個最近 action，而另外兩個近期 action 沒有直接鍵盤路徑。
- 在根目錄用搜尋取代三個旗艦情境。
- 用兩顆一點／三點按鈕控制資訊密度，或以長篇文字解釋開關。
- 將 `更多功能`、Esc 或密度控制做成醒目的主題色 CTA。
- 將 tray 已有的快捷鍵教學重複放進工具頁。
- 因為統一入口而刪除既有、已被熟練使用者記住的直接快捷鍵。
