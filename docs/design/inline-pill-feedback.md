# Inline Pill：狀態回饋設計

Pill 用來讓人知道正在發生什麼，不承擔文件閱讀。一般進度維持小膠囊；
需要說明或保護內容時，顯示「狀態標題 → 影響／內容狀態 → 下一步」通知卡。
卡片不顯示逐字稿、選單或捲軸。完整內容留在既有 owner，由明確複製 intent 取出。
原輸入欄仍持有焦點；卡片出現、更新或關閉都不得觸發貼上、潤飾或複製。

| 情境 | 呈現與下一步 |
| --- | --- |
| 麥克風啟動 | 「準備麥克風…」，可取消，尚不顯示假波形 |
| 聆聽中 | 真實音量波形與「聆聽中…」 |
| 沒收到聲音 | 波形歸平、「沒有收到聲音」，仍可繼續說話或停止 |
| 剩餘時間 ≤30 秒 | 顯示剩餘秒數與即將自動停止，不假裝已完成 |
| 停止／整理中 | 顯示整理狀態；若已選擇原文或潤飾，指示對應處理位置 |
| 正常辨識完成，等待選擇 | 「辨識完成」；說明短按原文、長按潤飾。可複製完整內容 |
| 語音服務中斷，已有部分內容 | 顯示型別化異常原因；說明已保留辨識文字、可原文貼上或複製，使用前確認完整性 |
| 無法啟動／權限遭拒／服務不可用／回應異常／辨識逾時 | 依原因顯示中文標題；沒有內容時不顯示複製，說明重新開始或權限／連線設定 |
| 完全沒有辨識文字 | 「沒有辨識到語音」，提示重新開始；不當作成功 |
| 時間上限／缺少語音片段 | 說明上限或內容不完整，保留已辨識文字，等待使用者決定 |
| 潤飾中 | ✦ 固定，圓周光條環繞；保留取消，不允許重複送出 |
| 潤飾失敗、逾時或服務不可用 | 「潤飾未完成」；原文保留，可原文貼上或複製；潤飾停用，不自動退回原文貼上 |
| 貼上中 | 顯示「貼上中…」與原文按鈕待處理狀態，不先報成功 |
| 已派送貼上快捷鍵 | 「已送出貼上，請確認原欄位」；只代表 dispatched_unconfirmed，沿用短暫終態停留 |
| 找不到原輸入欄 | 「找不到原輸入欄」；保留內容，可複製後手動貼上 |
| 貼上失敗 | 「尚未貼上」；保留完整內容，可手動複製貼上 |
| 貼上或剪貼簿清理無法確認 | 「貼上狀態需要確認」；先檢查原欄與剪貼簿，不建議直接重貼或宣稱尚未貼上 |
| 取消進行中 | 「取消中…」，直到 owner 收到實際確認 |
| 麥克風取消等待逾時 | 「取消等待逾時」；未送出貼上，停止狀態未能確認，提示檢查語音服務 |
| 取消未確認 | 「取消仍在確認」；尚未送出貼上，內容可複製，Esc 重試同一取消 |
| 取消完成 | 「已取消，沒有貼上」，沿用既有終態關閉時間 |
| 複製進行／成功／失敗 | 按鈕停用並顯示「複製中…」；真實 ack 後顯示「已複製」或「複製失敗」，可明確重試 |
| 長內容／多行內容／長診斷文字 | 通知卡尺寸不隨原文增長；不顯示逐字稿或原始診斷；複製不截斷 |
| 新互動取代舊互動／晚到結果 | 沿用 interaction identity guard；舊通知不得覆蓋新互動 |

## 邊框與版面

160×36 膠囊、24×24 圓形按鈕、六像素留白維持不變。輪廓由單一圓角描邊
在四倍解析度繪製後縮小，取消獨立頂部亮線，避免接合處粗細不一。
通知卡是 300×136 logical pixels；標題 13 px，說明 11 px，自動換行。
相鄰區塊先各自縮放取整，再相加定位，保護 125%／175% DPI 的邊緣。

## 架構診斷與決策

判定 Green；建議局部調整，信心高。觸發是同一 UI 模組多次改動，以及截圖中
原始英文錯誤、全文區與交付操作提示混在一起。可驗證事實是原實作建立
`tk.Text`／`Scrollbar`，且卡片直接顯示 `view.message`；更高維護成本是推論。

唯一語意 owner 是 `VoiceInputController`；`voice_visuals` 只擁有呈現模型與 raster，
`InlinePill` 只處理 Tk 排版與 native view lifecycle。這是所有 Inline 終態可重用的
回饋能力，不是某家語音 provider 的例外。保護既有完整內容、Copy identity、
取消與貼上真實 ack、不搶焦點與固定位置。

越界知識是任意 provider 英文診斷滲入產品文案。選擇在既有 frozen view 增加
typed capture notice，沿用既有 transport failure 類別；UI 不解析 message 字串。
原因隨原本 pending object 與 terminal effect 投影，不增加全域狀態、registry、
timer 或第二個 workflow owner。

若之後三次異常各自加英文比對，供應商文案變更就會同時破壞分類與版面；這是
債務乘數。保留原始卡片雖最便宜，但無法滿足清楚通知；全面重寫風險高且無證據
支持。主選項是上述局部調整，成本限定在既有 core/services/UI 邊界，可逐層還原。

順序為 typed fact → owner 投影 → 通知 projector → 移除閱讀控制 → raster 描邊。
防護是所有 transport failure × 有／無內容的服務與文案矩陣、完整 Copy 測試、
五種 DPI 的真實 Tk 卡片無裁切／重疊測試，以及架構層禁止閱讀／選單 widgets 與 no-activate 測試。
完成標準為每種狀態有短文案、無原始診斷或逐字稿、無捲軸、完整內容仍可複製。

此設計決策的代價是卡片不提供全文預覽；使用者可將完整內容複製至合適的編輯器。
若未來要求全文檢閱，需重新評估獨立閱讀 surface，不能把小通知卡改回編輯器。
仍未知的是使用者裝置上各家 provider 的實際失敗比例；此項影響文案優先級，
不影響本次 owner 與 presentation 邊界。
