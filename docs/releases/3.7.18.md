# ClipAI 3.7.18

Status: release preparation; not yet published. Final signing and distribution
admission remain pending. This document is the proposed public release body.

## Changes

- Managed updates allow up to 600 seconds for verified payload preparation and
  120 seconds for matching startup health, including a final sample at the
  deadline. Failed startup retains identity-scoped rollback to the previous app.
- Installed Windows venv processes are checked against their owned base runtime
  and signed logical installation, avoiding a false `identity_ineligible` error.
- Update downloads use bounded streaming, cancellation and accurate phase feedback.
- Saving valid provider settings restores the Tray ready state without a restart.
- Windows removal reports operation failures and offers retained-data removal
  by default, with separately confirmed full removal of ClipAI-owned data.

## Installation and upgrade

The proposed official Setup installs **ClipAI**, with its own installation and
shared-data roots. The acceptance **ClipAI Candidate** has a separate identity.
Candidate settings and API keys are not automatically imported into ClipAI;
keep Candidate data until a supported transfer or manual configuration is complete.

This release requires the **3.7.18 stable launcher**. Use the official Setup to
establish that launcher. Updating the app payload alone cannot update an older
stable launcher, runtime or verifier. Older installations must use the reviewed
Setup maintenance or retained-data reinstall procedure; that procedure must be
validated before publication. Do not manually remove versions or replace keyrings.

Offline installation and startup are supported by the bundled runtime and
dependencies; cloud AI, model refresh and updates require internet access.
